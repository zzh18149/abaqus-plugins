# Impact Repair CAI 0.4.0 — Abaqus 2024 / Python 3

独立插件，用于读取低速冲击后母板状态、建立平整补片及填充凹陷的胶层，并进行修理后压缩分析。保留原 `Composite_Repair_Strength_Analysis` 插件。运行环境为 Abaqus/CAE 2024、Python 3.10.5；使用用户材料时，需要原冲击作业对应的 VUMAT 和可用的 Fortran 编译环境。

## 与当前试验工艺的对应

实际工艺已确认：母板打磨等表面处理后，通过 LJM-170 胶膜与预固化补片二次粘接，使用热补仪固化；没有预填胶找平。当前“变厚胶层完全填充凹陷”的几何假设尚未与固化后的实际贴合状态核对。每面已确认一层胶膜，打磨后仅留下凹坑痕迹。0.12 mm 胶厚有公开资料支持，暂作参考；该试件固化后胶厚和粘接完整性尚未实测。详见 [试验工艺记录](EXPERIMENT_PROCESS.md)。

## Python 3 迁移

0.4.0 使用 Python 3 原生字符串处理中文界面和文件路径；配置仍为 UTF-8 JSON。源 ODB 及 STA 中可识别的求解版本必须为 2024。2022 的 ODB 升级不能代替 Explicit 状态库升级；请使用 2024 重新生成的冲击结果和配套状态文件。仍需对具体源数据进行 datacheck，不能仅凭版本号确认二进制状态兼容。旧版验证记录保留为历史证据，本次验证见项目根目录 `PYTHON3_MIGRATION_2024.md`。

## 安装与操作

本机默认输出目录：留空时使用 `F:\FEM\CAI_Runs\作业名`，不再写入 C 盘插件目录。手动填写的独立输出目录或已保存 JSON 中的 `output_dir` 仍优先使用；旧配置如指向 C 盘，请修改该字段或清空后重新生成。更新插件后请保存工作并重启 Abaqus/CAE。

0.3.2 的保存状态匹配改用按时间二分查找，只访问需要的帧，不再遍历大 ODB 的所有帧。最邻近选择、时间容差、OVERLAY 保存记录及自动回退规则不变。对本机 35 J 源数据，逐帧查找方案的读取约 197 秒，改后首次约 41 秒、同会话再次约 29 秒；此计时不含 CAE 母板导入和状态文件复制，受磁盘缓存与系统负载影响。

0.3.2 优化生成速度：补片节点和单元使用原生批量接口创建，减少母板表面扫描和 INP 解析的重复调用；同一 CAE 会话仅保留一个只读源 ODB 句柄，重复检查/建模时复用已加载的数据库。源 INP、ODB、STA 或状态库文件路径/大小/修改时间等变化时自动失效；遇到锁文件、读取失败或外部已关闭句柄时拒绝使用或重新打开。每次建模仍重新核对保存状态并读取 U/STATUS，不缓存 CAE 母板零件或改写材料状态。

消息区新增各阶段耗时和状态文件复制速度，`_model.json` 新增 `build_timings_seconds`。首次读取大 ODB 及每个独立方案的状态文件复制仍需时间，补片创建的加速倍数不能当作整次生成的加速倍数。独立副本策略不变，未使用硬链接、未省略状态文件。升级后保存当前工作并重启 CAE；需要在本会话替换/删除源文件前，可在 Kernel 命令行执行 `import cai_source; cai_source.close_source_cache()` 释放只读句柄。

0.3.1 修复底部按钮被页签区域挤出窗口的问题：“生成模型”“开始计算”“关闭”使用 Abaqus 原生底部操作栏，配置和报告区域恢复显示。升级后须重启 Abaqus/CAE，使已载入的旧界面代码失效。

1. 将整个 `ImpactRepairCAI` 文件夹放入用户的 `abaqus_plugins` 目录，例如 `C:\Users\用户名\abaqus_plugins\ImpactRepairCAI`。不要替换旧插件目录。重启 CAE。
2. 菜单 **Plug-ins → Impact Repair CAI 2024**。建议从空白模型数据库开始，避免把其他打开的模型一并保存到新 CAE 文件。
3. 指定同名的冲击 INP、ODB、原 VUMAT、母板实例名、材料名。步号、保存区间号和状态时间自动识别，无需填写。点击“检查源文件”。这一步自动识别最后分析步及其最后保存状态，并显示匹配的 ODB 帧和时间；二进制状态文件是否能成功导入，仍由输入检查验证。
4. 在“CAI 与输出”选择“冲击后压缩”或“修补后压缩”。前者直接使用继承损伤的母板，不创建补片或胶层；后者再设置补片轮廓、圆角、尺寸、每侧层数和角度及胶层参数。选择新的作业名和独立输出目录，然后点击底部“生成模型”。母板从 ODB 导入为孤立网格；Load 模块中可见 **CAIR_IMPACT_STATE** 初始状态预定义场。
5. 点击“输入检查”，在 Job Monitor 查看 `作业名_check`。这一步验证原状态库是否可读取、材料/截面/接触/约束是否被求解器接受。检查失败时先阅读 `.dat/.msg/.sta`。
6. 点击底部“开始计算”，在 Job Monitor 查看主作业。完成后点击“提取结果”和“刷新报告”。可在 Visualization 的 XY Data Manager 中查看 `CAIR_作业名` 载荷—位移数据。
7. JSON 配置可保存和重新加载。创建模型后改变建模参数，需要使用新作业名重新建模；提交时不会把新参数悄悄套用到旧输入文件。

默认自动选择最后 ODB 分析步的最后一帧，并与源 `.sta` 中记录的最后 Explicit 保存状态核对。若最后一帧没有相应保存状态，自动使用该步最后保存状态对应的 ODB 帧，并在消息区和模型报告中显示回退时间；如果最后保存状态没有对应 ODB 帧，则停止，避免把不同时间的几何和材料状态组合起来。自动识别需要保留同名 `.sta` 文件。

Explicit 保存状态与 ODB 帧是两种输出。自动模式由原生 InitialState 默认末步/末保存状态导入，不手工指定 STEP/INTERVAL。启用 OVERLAY 时，状态记录会覆盖，`.sta` 中可能始终显示 `Restart Number 1`，不能以“时间除以输出间隔”代替实际记录编号。旧 JSON 的手动设置仅保留给脚本兼容；GUI 载入配置后仍采用自动选择。

2022 的跨目录状态库引用存在启动器/求解器兼容限制，因此建模时会将 7 个必要状态文件复制为输出目录内的 `CAIR_IMPACT.*`，原件只读，不使用硬链接。当前 35 J 算例的副本需要约 20 GB 磁盘空间，各方案使用独立副本。模型中新增母板集合与表面位于装配层级，避免在 InitialState 省略原 Part 定义时丢失。

使用插件提交时会自动切换到方案输出目录；若打开 CAE 后手工提交，也必须以该目录为工作目录，使求解器找到 `CAIR_IMPACT.*`。修改模型后应使用新作业名重新生成，并保留关键字中的状态库引用和零初速度设置。


## 0.3.0 自动继承与两种模式

- 冲击数据页移除状态资格记录。旧配置中的 `source_equilibrated` 仅在读取时忽略，不再保存或作为强度输出门槛。
- 补片中心固定为母板参考网格包络中心；椭圆长轴与母板长轴平行。铺层角度仍按全局 X 定义，与轮廓转向分开。
- 单层厚度和层间几何厚度由母板 C3D8R/COH3D8 的参考 Z 区间自动提取。允许一层内部多层实体网格；若实际铺层厚度不统一，修补模式停止并说明歧义，不擅自取某层厚度。名义厚度为实体铺层厚度之和，排除 cohesive 几何厚度。
- 压缩轴固定 X。母板宽度/厚度、中心、铺层厚度和输出区间数不再需要输入。默认侧边支撑 5 mm、压缩时间 0.1 s、位移 2 mm、CPU 16。
- `analysis_mode=0` 为冲击后压缩，`analysis_mode=1` 为修补后压缩。无补片模式不创建补片材料、胶层、Tie；补片和胶层页面禁用。两种模式均使用原生 InitialState 继承状态，并保留压缩前平衡步与 X 向加载步。
- 场输出和历史输出从实际选中冲击步的 INP 输出请求继承，包括上一步传播而来的请求。保留原频率写法（区间数、时间间隔或默认设置）及适用于母板/全局的变量；原母板的输出集合映射到新装配集合。冲击头、旧夹具等不再存在的集合输出不复制，并在模型报告中列出。另按相同频率补充 U/RF、S/SDV/SDEG/STATUS、全局能量和两端 RF1/U1。实际输出以生成 INP 的继承关键字和 `_model.json` 的 `source.output_requests` 为准，不由旧配置中的区间数覆盖。
- 底部“生成模型”先写出 CAE/INP；“开始计算”提交该方案输入文件。更换模式或建模参数后需换作业名重新生成；相同设置的界面可直接提交，自动推导参数不会被误判为人工修改。

支持范围仍为参考几何中边沿平行于 X/Y、厚度沿 Z 的层合板。当前默认参数是按用户要求设置，不代表已经通过加载时间或边界收敛分析。

## 当前冲击算例

本机默认路径为 `F:\FEM\Impact\temp\35j_test.inp` 和同名 ODB。原作业记录的 VUMAT 为 `F:\FEM\Impact\HouhashinDel_fixed(1).for`。

- 母板实例 `PLATE-1`：150 × 100 mm，32 层，每层 0.14375 mm；材料名 `D_ZERO00`，100 个 SDV。
- 母板已有 172800 个 C3D8R、167400 个 COH3D8，共 340200 个单元；层间材料 `D_COHESIVE`。
- 名义层合板厚度为 4.6 mm。计入 31 个约 0.00001 mm 的层间几何间隔后，网格包络厚度约 4.60031 mm；强度归一化使用名义厚度。
- 源计算计划到 10 ms，但约 5.22 ms 被外部终止；ODB 最后场输出约 5.2 ms。自动匹配结果为步 1、5 ms 保存状态（OVERLAY 记录编号 1），**不是已经确认完成的冲击后平衡态**。
- 源文件中有材料损伤和单元删除。原文件仅被读取；不会自动重算、修改、升级或覆盖。

此算例的原始 VUMAT 与旧修理插件自带的 `hashinDel.for` 不同。不能用旧插件的 VUMAT 替换原作业 VUMAT。接口会校验 `.com` 中的路径并记录建模时 VUMAT 的 SHA-256，但无法证明源文件在原冲击求解后从未被修改；这需要用户保留原始版本。

## 建模约定

- 当前输入范围：Abaqus 2024 Explicit、单个未重新划分网格的平面 XY 母板实例、厚度沿 Z；实体铺层 C3D8R + COH3D8 层间。INP 需展开 INCLUDE。其他模型形式明确报错。
- 原母板的几何、材料状态、SDV 和已有层间损伤由原生 InitialState 导入。**不通过把 SDV 数值写成普通场变量来模拟损伤继承**。新补片材料沿用源母板参数，新补片内部 cohesive 材料沿用源层间参数。
- 轮廓：圆形（直径）、矩形（完整长宽）、椭圆形（完整轴长）；中心自动取母板未变形网格包络中心；不再输入中心和旋转角。椭圆较长的完整轴自动平行于母板较长的 XY 方向，矩形边与母板边平行。矩形可输入四周圆角半径，范围为 0 至短边的一半；0 保持直角，圆/椭圆忽略此值。圆弧由网格边近似，较小圆角应相应减小网格尺寸。轮廓由四边形网格近似，需做网格收敛检查。补片不能进入等效支撑带。
- 单面可选上或下。双面共用尺寸、角度序列和**每侧**铺层数，角度按全局 X 定义，序列均从母板向外排列。若需要镜像角度，需相应调整铺层定义，不能把层数理解成双面总数。
- 补片保持平整。胶层内表面跟随选定状态的母板表面，外表面为平面；最小间隙由胶厚参数控制。表面采用分片线性插值，不越过空洞外推。默认 `bond_void_policy=reject`：粘接面缺失时停止。用户可明确选择 `bridge`：保留完整补片，省略覆盖缺口的胶层单元，仅与完整母板表面粘接；不新增填充材料。采用投影多边形覆盖检查，连小于胶层网格的缺口也不会被自动粘住，因此未粘接区域可能被保守扩大，必须检查胶层网格敏感性。表面折叠仍会报错。
- 胶层和补片层间都使用真实 COH3D8 单元。通用接触从平衡步开始定义，以兼容 2022 的导入分析。层间与相邻补片铺层共节点；胶层—母板通过非匹配网格 Tie 连接，胶层自身承担损伤与脱粘。Tie 使用 Abaqus 2022 的 `main/secondary` 接口。
- 胶层采用 traction–separation + QUADS + 基于能量的 BK 混合模式演化，几何厚度作为本构厚度，所以输入 E/G 为 MPa 的模量，不能再次除以胶厚后输入。源补片层间保持源模型的单位本构厚度约定。
- 未模拟加热固化、固化收缩、热残余应力、去除损伤材料或胶膜流动。对深凹陷，实际胶膜能否填充以及增厚后的性能需要另行确认。

## CAI 边界与结果含义

参考 [ASTM D7137/D7137M-23](https://store.astm.org/d7137_d7137m-23.html) 的加载和防屈曲思路，采用工程等效约束：固定端限制压缩轴位移，加载端平滑施加轴向压缩位移，端部带及侧边限制面外位移，另设一个横向定位节点消除刚体平移。默认端部支撑带宽 12.5 mm、侧边支撑带宽 5 mm，均为可编辑的工程初值，**不是从标准完整夹具图核验得到的认证尺寸**。实际夹具接触、间隙、摩擦与单面补片引起的偏心效应需要通过边界敏感性分析/试验比较验证。

采用 Explicit，开启几何非线性，默认不进行质量缩放。原冲击速度设为零，然后进行压缩前平衡步及位移加载步；清零速度并不等于释放原冲击残余应力。若母板尚需卸载/回弹稳定，应先准备适合修理的冲击结束状态。完整厚度的边缘节点受面外约束，是等效支撑近似，也应检查其对局部分层/屈曲的影响。

输出文件：

| 文件 | 内容 |
|---|---|
| `作业名.cae`、`.inp` | 可检查/继续编辑的模型和求解输入 |
| `作业名_model.json`、`_config.json` | 实際参数、源文件、状态点、胶厚范围、本构文件指纹 |
| `作业名_curve.csv` | 压缩位移、加载/固定端合力、平衡误差 |
| `作业名_result.json`、`_report.txt` | 观察峰值、强度资格检查、警告及来源 |

强度定义为 `sigma_CAI = P_max / (原母板名义宽度 × 原母板名义厚度)`，补片和胶层厚度不计入分母。不是局部单元应力，也不是损伤区域的净截面应力。

提取器只处理 `.sta` 确认成功结束的作业；未完成或出错时明确报错。`observed_nominal_peak_MPa` 记录该次完整计算已观察的名义峰值。`cai_strength_MPa` 仅在以下检查通过时给出，否则为 null：作业成功结束；存在持续至少 5 个输出点、幅度至少 15% 的峰后下降；峰值附近（载荷不低于峰值 80%）动能/内能 ≤ 5%、人工能/内能 ≤ 5%、两端合力不平衡 ≤ 5%；平衡步末段动能/内能 ≤ 5%。状态资格记录及其人工勾选门槛已移除；源分析是否成功结束仍作为文件事实记录，不会伪称已确认卸载。阈值是工程数值判据，不是 ASTM 对有限元的强制条文。

这些检查不能代替网格、时间尺度和边界条件收敛研究，也不能排除局部惯性效应。材料仍为文献参考时，报告保留 `engineering_validated=false`。首次算例应比较加载时间加倍和网格加密后的峰值，并与可用 CAI 试验数据核对。首版采用指定最大位移的一次计算；没有峰后下降时需要延长分析，不自动把未达到的极限强度判为已获得。

## LJM-170 参考参数

默认取自朱渴鑫等，2026，《复合材料“W”形挖补修复结构的强度分析》，《力学与实践》48(1):55–62，[DOI 页面表 2](https://pubs.cstam.org.cn/article/doi/10.6052/1000-0879-25-181?viewType=HTML)。该文的载荷及接头形式并非本插件的冲击后贴补 CAI 工况。

| 参数 | 预设值 | 来源状态 |
|---|---:|---|
| E / MPa | 2200 | 文献表 2 |
| G / MPa | 815 | 文献表 2 |
| 法向/剪切起始强度 / MPa | 31.9 / 21.2 | 文献表 2 |
| GIc / N/mm | 0.48 | 文献表 2；1 kJ/m² = 1 N/mm |
| GIIc = GIIIc / N/mm | 1.83 | 文献表 2 |
| 参考最小胶厚 / mm | 0.12 | 单层厚度见 CN115742118A；2020 胶接试验也报告固化胶厚 0.12 mm，尚非本试件实测 |
| BK 指数 | 1.5 | 初始工程假设，需标定 |
| 密度 / tonne/mm³ | 1.2e-9 | 初始工程假设，需核实 |

单层厚度依据：[CN115742118A 具体实施方式及实施例 1](https://patents.google.com/patent/CN115742118A/zh)。该专利工艺与热补仪不同，仅用于厚度参考。参数仍控制程序的最小胶厚；当前变厚胶层不计算胶膜流动或单层用量守恒。浅凹坑完整粘接近似需与实际固化后的结构核对。

公开文献存在不同 LJM-170 参数组。例如 [2020 年《复合材料学报》论文](https://fhclxb.buaa.edu.cn/cn/article/pdf/preview/10.13801/j.cnki.fhclxb.20190308.001.pdf) 表 1 使用 E/G=3400/3400 MPa、强度=31.5/36.5 MPa、GIc/GIIc=0.9/1.0 N/mm。不要混合不同来源的局部参数拼成“厂家标定数据”。应根据胶膜批次、固化工艺、表面处理和相应接头试验选择/标定。

## 自动化接口与验证

CAE Kernel 中：

```python
import sys
sys.path.insert(0, r'你的路径\ImpactRepairCAI')
import cai_kernel
cai_kernel.execute(config_path=r'你的路径\settings.json', action='build')
```

`action` 支持 `inspect`、`build`、`datacheck`、`submit`、`results`。后两类提交通过 Job Monitor 异步跟踪。配置字段、量纲和默认值见 `cai_config.py`；JSON 不执行表达式。参考 `examples/35j_reference.json`。默认 `state_selection=auto`，其中旧的步号/时间字段不参与选择，建模后写回实际采用值。

命令行可用 `abaqus cae noGUI=run_cai.py -- settings.json build`。`datacheck` 和 `submit` 是异步提交；在本机无 GUI 环境中，`waitForCompletion()` 曾立即返回且状态为 None，因此批处理应确认 `.sta` 成功结束再提取，或在输出目录用 `abaqus job=作业名 input=作业名.inp user=原VUMAT路径 cpus=核数 double=both interactive` 等待求解。路径有空格时需要加引号。不要用该命令覆盖已有结果。

纯 Python 检查：`python -m unittest discover -s tests -v`。实际 Abaqus 验证记录见交付目录中的 `VALIDATION.md`。小型流程测试只证明对应流程/API可执行，不代表已获得该 35 J 大模型的压缩强度。

技术依据：[Abaqus Initial state](https://docs.software.vt.edu/abaqusv2025/English/SIMACAECAERefMap/simacae-t-lbihelptopicsinitialstate.htm)、[Explicit → Explicit 状态传递](https://abaqus.uclouvain.be/English/SIMACAEANLRefMap/simaanl-c-exptoexp.htm)、[*IMPORT 区间定义](https://abaqus.uclouvain.be/English/SIMACAEKEYRefMap/simakey-r-import.htm)。跨维护版本的二进制状态兼容性需要实际核对，单纯升级 ODB 并不能解决状态文件的兼容问题。
